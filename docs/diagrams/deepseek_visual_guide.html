Overview

A raw-PyTorch decoder combines Multi-Head Latent Attention, fine-grained MoE and optional multi-token prediction. The canonical model uses 18 layers: two dense layers followed by sixteen MoE layers. Configuration and implementation gaps are disclosed rather than presented as a working end-to-end training run.

Model

Configured width is 768, with 12 heads and vocabulary 100,018. MoE uses 20 routed experts, top-4 selection and one shared expert. The MLA cache stores 192 latent plus 24 positional values per token per layer. The manual path computes in latent space, while default SDPA reconstructs expanded keys and values.

Data

The shared seven-source corpus recipe is not a verified corpus inventory. Its raw packed shard output is incompatible with the project consumer that uses torch.load to read PyTorch-serialized tensors. A format adapter is required before the drawn producer-to-consumer handoff can work. Preparation budget and training exposure are distinct.

Training

Cross-entropy precedes the finite-loss gate. Four configured micro-batches accumulate into one optimizer update. MoE bias updates use the optimizer clock, while periodic saves use micro-step cadence. Checkpoints do not restore exact sampler order or pending gradients. Canonical YAML places mtp_loss_weight under model, but the CLI reads it from training, leaving MTP disabled through that entry point.

MLA and optimization budgets

Logical MLA cache arithmetic is not physical allocation: the cache reserves at least 16 batch slots and the configured maximum sequence length. The FP32 master model cannot be budgeted as BF16 parameter storage. Triton acceleration, speculative acceptance and throughput need their own measurements. The obsolete calculator and random bias simulation were removed because their dimensions and behavior did not match the canonical implementation.
